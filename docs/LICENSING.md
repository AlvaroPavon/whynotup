# Licencia y atribución

La distribución actual de WhyNotUp utiliza **zlib/libpng License with Acknowledgement**, identificador SPDX **`zlib-acknowledgement`**. El texto aplicable está en [LICENSE](../LICENSE); [NOTICE](../NOTICE) identifica al autor y al proyecto original.

Puedes usar, modificar, vender y redistribuir el software, incluidos forks con otro nombre. Las condiciones de esta licencia son:

1. No falsear el origen ni afirmar que escribiste el software original. Si utilizas el software en un producto, su documentación debe incluir el reconocimiento indicado en la licencia.
2. Marcar claramente las versiones de código fuente modificadas y no presentarlas como el software original.
3. No eliminar ni alterar el aviso de licencia de ninguna distribución del código fuente.

El reconocimiento requerido en la documentación del producto es:

```text
Portions Copyright (c) 2026 Álvaro Pavón (AlvaroPavon)
```

Conservar solo el archivo de licencia no sustituye la condición de reconocimiento en la documentación del producto. Recomendamos una sección visible «Origen y atribución» en el README o documentación principal del fork, por ejemplo:

> Portions Copyright (c) 2026 Álvaro Pavón (AlvaroPavon)
>
> Este proyecto deriva de [WhyNotUp](https://github.com/AlvaroPavon/whynotup), creado por Álvaro Pavón (AlvaroPavon). Esta es una versión modificada, mantenida por [nombre del mantenedor].

El enlace, ese texto explicativo y su ubicación en el README son recomendaciones. La licencia exige reconocimiento en documentación del producto, pero no prescribe un archivo, posición o diseño concretos. Puedes atribuirte tus propias modificaciones distinguiéndolas de la autoría original. El nombre del fork puede cambiar.

## Alcance de esta explicación

`zlib-acknowledgement` es una variante recogida por SPDX; no es la licencia Zlib normal, que deja el reconocimiento documental como opcional. Su presencia en SPDX no equivale a aprobación de la Open Source Initiative: los datos SPDX no la marcan como aprobada por OSI. No la anunciamos como una licencia aprobada por OSI.

Esta página resume y ejemplifica las condiciones; no las amplía ni reemplaza [LICENSE](../LICENSE). Ninguna elección de licencia garantiza el cumplimiento por terceros ni una resolución judicial concreta. La compatibilidad con otras licencias y una disputa específica requieren un análisis propio.

Fuentes: [texto SPDX](https://spdx.org/licenses/zlib-acknowledgement.html), [plantilla y metadatos oficiales SPDX](https://github.com/spdx/license-list-data/blob/main/json/details/zlib-acknowledgement.json), [guía de GitHub sobre cambios de licencia](https://opensource.guide/legal/#what-if-i-want-to-change-the-license-of-my-project).
